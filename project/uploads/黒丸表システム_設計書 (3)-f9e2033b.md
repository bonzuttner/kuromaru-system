# 黒丸表システム 設計書

**対象**: キリン堂様 期限管理／配送割当（黒丸表）
**目的**: マスタ・設定から「どの店舗に何を発送するか」「どの商品をいつどこに発送するか」を自動算出する仕組みと、その入力モックアップを作成するための設計

> 改訂メモ:
> - 最終成果物を「発送情報（出荷リスト）」と明確化。
> - 黒丸表は複数作成でき、1つの黒丸表に複数の商品カテゴリを含められる。
> - **商品カテゴリ（湿布・風邪薬・胃腸薬 等）を追加。** 1シートに複数カテゴリを載せる運用に対応。
> - **同一商品が複数の設定から重複して●判定される場合のルールを確定。** 配送情報が一致すれば1件に統合、異なれば別レコードとして残す。
> - **棚割りに「棚割りイメージ画像」を追加。** 単位ごとに1画像（実際の陳列見本）を紐付ける。画像内の枠の数＝送る商品の種類数と一致する。
> - **店舗マスタ・商品マスタをCSVインポートで一括登録・更新できるようにする。**
> - **【構造変更・確定】商品テーマ・棚本数を恒久マスタとして持つのをやめ、黒丸表を作成するたびにその場で設定する方式に変更。** マスタは「店舗マスタ／商品マスタ／商品カテゴリマスタ」の3つのみとし、単位（棚本数）・棚割り・使用商品・配送情報は**黒丸表ごとに都度入力**する。●の自動算出ロジック自体は変わらない。

---

## 1. 概要

### 1.1 背景
現行の黒丸表は、店舗ごとの送付対象商品を担当者が手作業で「●」を打ち込んで管理している。店舗数が多く（キリン堂 約339店舗）、施策ごとに黒丸表を都度作成するため、手作業の修正負荷とミスのリスクが大きい。また、1枚の黒丸表に湿布・風邪薬など複数カテゴリの商品を載せることもある。

### 1.2 目的・最終成果物
マスタと、黒丸表ごとの入力をもとに、黒丸表の送付対象（●）を**自動算出**し、最終的に次の2つの**発送情報**を出力する。

- **店舗別発送リスト**: どの店舗に、何を発送するか
- **商品別発送リスト**: どの商品を、いつ、どこに発送するか

担当者が触るのは「マスタの入力」と「黒丸表ごとの設定入力」のみとし、黒丸表本体と発送情報は計算結果として生成する。

### 1.3 設計の基本方針
- データを「マスタ（恒久）」「黒丸表ごとの設定（都度入力）」「黒丸表（出力）」「発送情報（最終成果物）」に分離する。
- 同じ情報を二重に持たない（店舗情報・商品情報は1か所で管理）。
- **黒丸表は複数作成できる**。施策・配送タイミングごとに1つ作る運用を想定。
- **1つの黒丸表に複数の商品カテゴリを載せられる**（例: 湿布＋風邪薬を1シートに）。
- **商品カテゴリは複数の商品マスタを紐付けるグループ**として定義し、**商品マスタを登録する際に、どのカテゴリに属するかを設定する**。
- **【確定】単位（棚本数）・棚割り（単位→棚割り数→送る商品）は、恒久マスタとして持たない。** 黒丸表を作成するたびに、その黒丸表用として都度入力・設定する。

## 2. システム全体構成

データは「マスタ（恒久）」「黒丸表ごとの入力（都度）」「黒丸表（出力）」「発送情報（最終成果物）」で構成する。

### 2.1 マスタ（恒久・使い回す）

| # | 名称 | 役割 |
|---|------|------|
| 1 | 店舗マスタ | 店舗の基本情報を最新化して保持。CSVインポート対応 |
| 2 | 商品マスタ | 商品そのものの情報（恒久カタログ）。登録時にどの商品カテゴリに属するかを設定。CSVインポート対応 |
| 3 | 商品カテゴリマスタ | 複数の商品マスタを紐付けるグループ（湿布・風邪薬・胃腸薬 等） |

### 2.2 黒丸表ごとに都度設定するもの（マスタとして保存しない）

| # | 名称 | 役割 |
|---|------|------|
| 4 | 単位設定（旧・棚本数） | その黒丸表について、店舗ごとに単位（4〜8本）を都度設定 |
| 5 | 棚割り設定（旧・商品テーマ） | その黒丸表について、単位 → 棚割り数 → 送る商品の対応を都度設定。棚割りイメージ画像を含む |
| 6 | 商品カテゴリ・使用商品の選択 | その黒丸表に含めるカテゴリ（複数可）と、カテゴリ内で実際に使う商品を選択 |
| 7 | 配送情報 | 対象商品ごとに付属する配送・販促の段取り |
| 8 | 配送マッピング | 単位×棚割り×商品の設定を組み合わせ、黒丸表を作成（●を自動算出） |

### 2.3 出力・最終成果物

| # | 名称 | 区分 | 役割 |
|---|------|------|------|
| 9 | 黒丸表 | 出力（複数作成） | 4〜8の入力から、店舗ごとの●を自動表示 |
| 10 | 発送情報 | 最終成果物 | 全黒丸表を集約した発送リスト（店舗別／商品別） |

### 2.4 データの関係（構造）

```
【マスタ（恒久）】
店舗マスタ
商品マスタ（→ 商品カテゴリマスタに紐付け）
商品カテゴリマスタ

            ↓ 黒丸表を作成するたびに、以下を都度入力
【黒丸表ごとの入力（都度・保存しない）】
  1. 単位設定：店舗マスタの各店舗に、この黒丸表での単位（4〜8本）を設定
  2. 棚割り設定：単位 → 棚割り数 → 送る商品 の対応を設定（棚割りイメージ画像を含む）
  3. 商品カテゴリ・使用商品の選択：カテゴリ（複数可）と、カテゴリ内の使用商品を選択
  4. 配送情報の設定：対象商品ごとにCD・JAN・入稿期限・店舗着日等
  5. 配送マッピング：1〜4を組み合わせて黒丸表を作成 → ●を自動算出

            ↓
        [黒丸表 A]  [黒丸表 B] …（施策ごとに複数作成）
            ↓
      （全黒丸表の●を集約）
            ↓
    ┌──────────────┐
    │   発送情報    │  最終成果物
    ├──────────────┤
    │ 店舗別: 店舗 → 送る商品           │
    │ 商品別: 商品 → いつ・どこへ送る   │
    └──────────────┘
```

### 2.5 商品の階層

```
商品マスタ（個々の商品）
   ↑ 紐付け（複数）／商品登録時にカテゴリを指定
商品カテゴリマスタ（例: 湿布 = サロンパス, メルジン…, アンメルツ）
   ↑ 黒丸表を作成する際に、このカテゴリの中から使用する商品を選択
```

### 2.6 ●の算出ロジック（黒丸表内）

```
[単位設定（黒丸表ごと）]   店舗 ──→ 単位（例: 4本単位）
                                │
[棚割り設定（黒丸表ごと）]      ▼   ※黒丸表に含まれる各カテゴリで実行
                    単位 ──→ 棚割り数 ──→ 送る商品（例: ②③④⑤）
                                │
[黒丸表]         該当店舗 × 該当商品列に ● を自動表示
```

> ロジック自体（単位→棚割り数→送る商品→●表示）は変わらない。変わったのは、これらの設定を恒久マスタとして持つか、黒丸表を作るたびに都度入力するかという点のみ。

## 3. データ定義

### 3.1 店舗マスタ（恒久マスタ）
店舗の基本情報。クライアントから提供される最新情報で更新する。CSVインポートによる一括登録・更新に対応する。

| 項目 | 例 | 備考 |
|------|-----|------|
| 店番（店舗コード） | 0064 | 検索キー。各表からこのコードで参照 |
| ストアネーム | キリン堂 | |
| 店舗名称 | 亀山店 | |
| 正式名称 | キリン堂亀山店 | ストアネーム＋店舗名称で生成 |
| 郵便番号 | 519-0124 | |
| 住所 | 三重県亀山市東御幸町222 … | 発送先住所として発送情報で使用 |
| 電話番号 | 0595-82-7821 | |

> CSVインポート仕様（たたき台）: 店番（店舗コード）をキーに、既存レコードは上書き更新、新規店番は追加登録する。クライアントから随時提供される最新CSVをそのまま取り込める形を想定。

### 3.2 商品マスタ（恒久マスタ）
商品そのものの情報（恒久的なカタログ）。配送条件とは切り離して管理する。登録時に、どの商品カテゴリに属するかを設定する。CSVインポートによる一括登録・更新に対応する。

| 項目 | 例 | 備考 |
|------|-----|------|
| 商品ID | P00001 | 一意キー。CSVインポート・各表からの参照キー。クライアント側が既に持つ商品コードをそのまま使用（システム側での自動採番は行わない） |
| 商品名 | サロンパス 40枚入 | SKU単位でも保持可 |
| 商品カテゴリ | 湿布 | 商品マスタ登録画面の中で設定（商品カテゴリマスタから選択） |
| メーカー／ブランド／分類 等 | 久光製薬／サロンパス／第3類医薬品 | 必要に応じて保持 |

> CSVインポート仕様（確定）: 商品IDをキーに、既存レコードは上書き更新、新規の商品IDは追加登録する。商品IDはクライアントの既存商品コードをCSVにそのまま含めてインポートする運用とし、システム側での自動採番は行わない。これにより、再インポート時も同じ商品コードで確実に同一商品と突合できる。CSVには商品カテゴリの列を含め、登録と同時にカテゴリ紐付けも取り込む想定。

### 3.3 商品カテゴリマスタ（恒久マスタ）
複数の商品マスタを紐付けるグループ。湿布・風邪薬・胃腸薬などの区分。1つの黒丸表に複数カテゴリを載せられる。カテゴリと商品の紐付け自体は、商品マスタ側（3.2）の登録時に設定する。

| 項目 | 例 |
|------|-----|
| カテゴリ名 | 湿布 |
| 紐付く商品マスタ（複数・商品マスタ側から設定） | サロンパス／メルジン・ロキエフェクト／フェイタスジクサス／バンテリン／アンメルツ |

> 今回の対象カテゴリ: 湿布（5商品）。将来、同じシートに「風邪薬」「胃腸薬」などを並べて作成することがある。

### 3.4 単位設定（黒丸表ごと・都度入力／マスタとして保存しない）
その黒丸表について、店舗ごとに「何本単位の什器を置くか」を設定する。恒久マスタとしては持たず、黒丸表を作成するたびに都度設定する。

| 項目 | 例 |
|------|-----|
| 店舗コード | 0159 |
| 店舗名称 | 名張中央店 |
| 単位（4本／5本／6本／7本／8本） | 6本単位 |

> CSVでの取り込み（黒丸表ごとに都度実行）: 実データに合わせ、CSVは「店舗コード／店舗名称／4本／5本／6本／7本／8本」の横持ち（one-hot）形式とする。該当する単位の列にのみ「1」を立て、他は空欄とする。取り込み時に「1」が立っている列を、その店舗の単位として黒丸表内に一時保存する（恒久マスタへの保存はしない）。
>
> - 異常データの扱い（要確認）: 1行の中で複数列に「1」が立っている場合、またはどの列にも「1」がない場合のエラー処理を別途定義する必要がある。

### 3.5 棚割り設定（黒丸表ごと・都度入力／マスタとして保存しない）
その黒丸表について、カテゴリ内の商品に対する陳列パターン「単位 → 棚割り数 → 送る商品」を設定する。恒久マスタとしては持たず、黒丸表を作成するたびに都度設定する。

棚割り設定が持つ情報:
- 対象カテゴリと、その構成商品（カテゴリ内で使用する商品の選択と対応）
- 単位ごとの棚割り数（4、5 など）
- 棚割り数に応じて送る商品の組み合わせ
- 単位ごとの棚割りイメージ画像（1単位＝1画像。実際に棚に商品を並べた見本写真。画像内の枠の数＝送る商品の種類数と一致する）

現行の棚割り設定例（カテゴリ: 湿布）— 要確認:

| 単位 | 棚割り数 | 送る商品 | 棚割りイメージ |
|------|---------|----------|----------------|
| 4本単位 | 4 | ②③④⑤（サロンパス① を除く4商品） | （4本単位用の見本画像を別途登録） |
| 5・6・7・8本単位 | 5 | ①②③④⑤（全5商品） | 図1.png（5商品分、枠5つ＝商品5種） |

> 商品番号: ①サロンパス ②メルジン・ロキエフェクト ③フェイタスジクサス ④バンテリン ⑤アンメルツ

### 3.6 商品カテゴリ・使用商品の選択（黒丸表ごと）
黒丸表を作成する際、対象とする商品カテゴリを複数選択し、各カテゴリについて商品マスタの中から実際にその黒丸表で使う商品を選択する。

- 1つの黒丸表に複数カテゴリを含められる（例: 湿布＋風邪薬）
- カテゴリ内の全商品を使う必要はなく、一部の商品だけを選択することも可能

### 3.7 配送情報（黒丸表ごと・対象商品に付属）
その黒丸表で対象となった商品ごとに付属する、配送・販促の段取り。黒丸表のヘッダー部に表示される。

| 項目 | 例 | 備考 |
|------|-----|------|
| CD | K80221 | 商品コード |
| 入稿期限 | 2025/12/23 | |
| 店舗着 | 2026/1/24 | 発送情報「いつ」の基準 |
| ラウンダー | 2026/1/26 | |
| 開始日 / 終了日 | （指示があれば） | |
| ピッキングJAN | 9999999990762 | |
| 帯 パターン | 1 | |
| 同梱販促物 | ×／○ | |

> カテゴリ・商品ごとに配送日程が異なる場合があるため、配送情報は黒丸表内の対象商品ごとに持つ。

### 3.8 黒丸表（出力・複数作成）
施策・配送タイミングごとに作成する送付指示表。1つの黒丸表は、以下の都度入力（3.4〜3.7）を組み合わせた「配送マッピング」によって自動算出される。

- 対象カテゴリ（1つ以上）と、各カテゴリで選択した使用商品・棚割り設定・配送情報
- 対象店舗の範囲と、その黒丸表用の単位設定
- 店舗ごとの●（自動算出）

| 列 | 項目 | 取得元 |
|----|------|--------|
| A〜B | エリア名・BL名 | 手入力（組織区分） |
| C | 店舗コード | 手入力（キー） |
| D〜I | 店舗名称・住所・電話等 | 店舗マスタ から自動 |
| J〜N | 4本〜8本 | その黒丸表の単位設定（3.4）から自動 |
| O | 展開数 | 単位×本数 で自動計算 |
| 商品列（カテゴリごと） | 各商品の●（送付対象） | その黒丸表の棚割り設定＋単位設定から自動算出 |
| ヘッダー部 | カテゴリ名・商品名・CD・各期限・JAN・帯・棚割りイメージ等 | 商品カテゴリ／棚割り設定（棚割りイメージ含む）／商品マスタ／配送情報 から表示 |

> 複数カテゴリを含む場合、商品列はカテゴリごとにまとまって並ぶ（湿布の商品群＋風邪薬の商品群…）。ヘッダーにカテゴリ名（例: 湿布）を表示する。

### 3.9 発送情報（最終成果物）
全黒丸表の●を集約し、実際の発送に使う2つのリストを生成する。

(A) 店舗別発送リスト — どの店舗に何を発送するか

| 項目 | 例 |
|------|-----|
| 店舗コード／店舗名称／住所 | 0159 名張中央店 / 三重県… |
| カテゴリ・送る商品（CD・JAN） | 湿布 / ①サロンパス K80221 … |
| 数量 | 棚割り数に応じた数 |
| 店舗着日 | 2026/1/24 |
| 由来の黒丸表 | 黒丸表A |

(B) 商品別発送リスト — どの商品をいつどこに発送するか

| 項目 | 例 |
|------|-----|
| カテゴリ・商品（CD・JAN） | 湿布 / ②メルジン・ロキエフェクト K80222 … |
| 発送タイミング（入稿期限・店舗着） | 入稿 2025/12/23 / 店舗着 2026/1/24 |
| 宛先店舗（一覧・合計店舗数） | 名張中央店 ほか 305店 |
| 由来の黒丸表 | 黒丸表A |

## 4. 算出ロジック

### 4.1 黒丸表内の●判定
各黒丸表 × 各カテゴリ × 各店舗について、その黒丸表で設定された「単位設定」「棚割り設定」をもとに、以下で判定する。

1. 店舗の単位を取得 … その黒丸表の単位設定（3.4）から、その店舗の単位（例: 4本単位）。
2. 棚割り数を決定 … その黒丸表の棚割り設定（3.5）で、単位 → 棚割り数（例: 4）。
3. 送る商品を決定 … 棚割り設定で、棚割り数 → 送る商品（例: ②③④⑤）。
4. ●を表示 … 該当商品列に●。黒丸表に複数カテゴリが含まれる場合は、それぞれのカテゴリについて1〜4を繰り返す。

算出例（カテゴリ: 湿布）

| 店舗 | 単位 | 棚割り数 | 送る商品 | 結果 |
|------|------|---------|----------|------|
| 0169 沢良宜店 | 4本 | 4 | ②③④⑤ | ②③④⑤に● |
| 0168 阪南石田店 | 5本 | 5 | ①②③④⑤ | 全商品に● |
| 0159 名張中央店 | 6本 | 5 | ①②③④⑤ | 全商品に● |

### 4.2 発送情報への集約
全黒丸表・全カテゴリの●を走査し、

- 店舗別: 店舗ごとに●が付いた商品（カテゴリ込み）をまとめ、配送情報（CD・JAN・店舗着日）を付与。
- 商品別: 商品ごとに●が付いた店舗をまとめ、発送タイミングと宛先店舗数を算出。

> 同じ店舗が複数の黒丸表に登場する場合は、黒丸表（施策）単位で別々の発送として扱う。
>
> 同じ黒丸表内で、同じ店舗・同じ商品に重複して●が付いた場合（確定ルール）:
> - 各設定に紐づく配送情報（CD・JAN・店舗着日等）を比較する。
> - 配送情報が完全に一致する場合 → 1件のレコードに統合する（実際の発送は1回のため、重複計上しない）。
> - 配送情報が一部でも異なる場合 → 発送のタイミング・内容が異なる実態を反映し、別レコードとして残す。

## 6. 確認事項・未確定事項

1. 棚割り数と送る商品の対応（3.5）: 単位ごとに固定か、黒丸表ごとに自由設定か。
2. 黒丸表の単位: 1黒丸表＝1施策か、1配送タイミングか（複数作成の区切り）。
3. 1黒丸表内の複数カテゴリ: 商品列はカテゴリごとに横並びでよいか、別表示か。
4. 発送の数量: 「数量」は棚割り数そのものか、別途定義が必要か。
5. 同一店舗が複数黒丸表に登場するケースの集約ルール（別発送扱いでよいか）。
6. 発送情報の出力形式: 画面表示のみか、CSV／帳票での出力も必要か。
7. エリア名・BL名（A〜B列）: 手入力のままか、店舗マスタに持たせるか。
8. 4本単位の棚割りイメージ画像が未提供（3.5）: 今回いただいた図1.pngは5本単位（5商品分）の見本。4本単位用の見本画像を別途ご提供いただく必要がある。
9. 店舗マスタ・商品マスタのCSVインポート仕様（3.1, 3.2）:
   - 商品マスタの一意キーは商品ID（クライアントの既存商品コード、自動採番なし）で確定。
   - CSVの文字コード（Shift-JIS／UTF-8）・区切り文字・ヘッダー行の有無。
   - 既存データとの突合ルール（キー一致で上書き／新規追加、削除された行の扱い）。
   - 不正な行（必須項目欠落等）があった場合の取り込み時エラー処理（一部のみ取り込むか、全体を差し戻すか）。

12. NEW: 黒丸表を作成した後の設定変更: 一度作成した黒丸表の単位設定・棚割り設定を後から編集できるか、編集した場合●は再計算されるか。
